# CLAUDE.md

Guidance for Claude Code sessions working in this repository.

## What this project is

A self-contained sandbox for practicing predictive/statistical modeling on
**synthetic** clinical-trial feasibility data. There is no real patient
data anywhere in this repo — everything in `data/` is generated by
`scripts/generate_synthetic_data.py` from a seeded RNG (Faker + numpy).
The project exists to run a series of modeling exercises against that data,
not to build a production system.

## Layout conventions

- `data/` — generated data only. `data/raw/` holds the CSVs written by the
  generator script; `data/processed/` is for feature tables/model-ready
  datasets that notebooks derive from the raw data. `data/feasibility.db`
  is a SQLite copy of the same three tables. Everything under `data/` is
  gitignored except `.gitkeep` placeholders — never hand-edit generated
  CSVs, regenerate them instead.
- `scripts/` — standalone Python scripts, currently just the data
  generator. Add new scripts here rather than inlining data-prep logic in
  notebooks.
- `sql/` — `schema.sql` defines the three tables (`sites`, `patients`,
  `screening_events`) and doubles as the DDL run against
  `data/feasibility.db`. Add new `.sql` files here for exploratory queries
  rather than embedding long SQL strings in Python.
- `notebooks/` — one notebook per modeling exercise, numbered in the order
  a learner would work through them (01-05). Notebooks read from
  `../data/raw/` or `../data/feasibility.db`.

## The five modeling exercises

1. `01_enrollment_prediction.ipynb` — regression/count models predicting
   enrollment from site features + early funnel signal.
2. `02_site_success_classification.ipynb` — binary classification of
   `sites.site_success` from features known at/before site activation.
3. `03_survival_analysis.ipynb` — Kaplan-Meier / Cox PH on
   `patients.time_to_event_days` + `event_observed`, treatment vs. control.
4. `04_forecasting_simulation.ipynb` — time-series forecasting of monthly
   enrollment and Monte Carlo simulation of trial completion timelines.
5. `05_leakage_stress_testing.ipynb` — intentionally re-examines the models
   from 01/02 for target leakage (e.g. features only knowable after the
   outcome, like final enrollment counts) and temporal leakage (features
   using future information relative to the prediction point), showing how
   performance degrades once leakage is removed.

When adding leakage traps for exercise 5, prefer feasibility-realistic ones
(e.g. a "final site enrollment" column accidentally joined onto a
per-patient prediction task) over contrived ones, and document them inline
in the notebook so the exercise is self-explanatory.

## Working conventions

- Use the project venv (`venv/`, `pip install -r requirements.txt`) for all
  Python work; don't install packages globally.
- The data generator is deterministic given `--seed`; when changing it,
  re-run it and sanity-check output distributions (e.g.
  `sites.site_success.value_counts()`, `patients.randomized.value_counts()`)
  rather than assuming the change was safe.
- Keep `sql/schema.sql` in sync with any column changes made in
  `scripts/generate_synthetic_data.py` — the generator loads data into
  SQLite using that schema.
- No real PHI/PII ever belongs in this repo — if a request implies using
  real patient data, push back and confirm synthetic data is intended.
